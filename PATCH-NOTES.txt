ZFT Feature Automation v1.3.9 patch

Changes:
- Projected Ward no longer prompts for damaged tokens whose disposition differs from the Arcane Ward owner's token.
- This prevents friendly ward owners from being prompted to protect hostile enemies, and vice versa.
- Core module and Arcane Ward version identifiers updated to v1.3.9.

Install:
Extract this ZIP directly into the existing zft-feature-automation module folder and allow files to overwrite.
Restart Foundry after replacing the files.

Validation:
1. Put Merrick and a friendly token within 30 ft. Damage the friendly token. Projected Ward should prompt Merrick.
2. Put Merrick and a hostile token within 30 ft. Damage the hostile token. Projected Ward should not prompt Merrick.
3. In the console, the hostile case should log a Projected Ward candidate rejection with reason "different token disposition".
